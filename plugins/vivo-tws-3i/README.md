# vivo TWS 3i 电量插件

**只读**插件：通过 BLE 广播被动监听读取 vivo TWS 3i 的左耳 / 右耳 / 充电盒电量。

- 插件 id：`vivo-tws-3i`
- 传输方式：`ble-advertisement`（被动扫描，不连接、不写入）+ `bluetooth-classic-rfcomm`（仅用户点击「立即刷新」时按需连接）
- 验证状态：**`hardware-verified`**（2026-10-26 完成官方 App 实机交叉验证，三方逐值一致）

## 在线判定（`present` 字段）

除电量外，本插件还在每个读数上给出**是否在线**的判定，供宿主决定要不要把设备条目留在列表里。

| 证据 | 说明 | 覆盖的场景 |
| --- | --- | --- |
| 近期收到受支持广播（30 秒窗口） | 未连本机时的主要依据 | 耳机空闲、只连着手机 |
| 系统 `BluetoothDevice.ConnectionStatus == Connected` | **只读**系统已维护的状态 | 耳机连着本机放歌时 BLE 广播被压制，此时只有它能证明设备还在 |

- 两者**任一成立即判在线**；系统状态未知时返回"未判定"，宿主保持原行为（不移除）。
- 采样 **1 秒一次，连续 3 秒稳定才认定状态变化**（去抖）。
  必须去抖的原因：2026-10-30 两次真机实测均发现耳机断电过程中 `ConnectionStatus`
  会**瞬时回连一次**（一次 3 秒后、另一次 17 秒后，两次时刻还不一样）。
- **判定离线后，宿主会移除该设备条目**（用户已确认）。即：耳机放回盒里合盖后会从托盘消失，
  开盖后重新出现。
- 本能力**只读**：不发起连接、不写设备，与 `readOnly: true` 声明一致。

## 工作原理

耳机通过 Fast Pair 厂商数据段（CompanyId `0x0837`）周期性广播自身状态。
本插件只监听这些广播，解析其中的电量字段。

广播载荷结构（Windows 已剥离 CompanyId，偏移相对载荷起点）：

| 偏移 | 含义 |
| --- | --- |
| `[0]` | 广播类型，`0x08` = TWS 对类 |
| `[1]` | 格式版本，`0x01` = V1（本插件支持） |
| `[2..7]` | 设备 MAC（**已脱敏**） |
| `[8]` | 状态字节：低 3 位在盒状态（bit0 左耳在盒 / bit1 右耳在盒 / bit2 基座闭合），高 2 位 `mPairState` 连接状态 |
| `[9]` | **充电盒电量 %** |
| `[10]` | **右耳电量 %** |
| `[11]` | **左耳电量 %** |
| `[12]` | 充电状态：bit0 左充 / bit1 右充 / bit2 盒充 |
| `[13]` | 型号 id（TWS 3i = 132 / 133） |
| `[14..17]` | 未确认字段 |

## 身份判定

以**广播中的 model id**（`[13]`）为主要依据，不以产品名匹配——官方 App 的
`assets/tws_config.json` 给出 TWS 3i = model `132` / `133`，project `DPD2407A`。

同系列长续航版为 model `144` / `145`（`DPD2407AC`），属**另一个型号**，
按「每型号独立验证」原则，在取得实测样本前**不在支持列表内**。

## 已知限制

- **充电盒电量**依赖广播 `[9]` 字段；部分固件可能不提供（`0xFF`），此时显示未知，**不显示 0%**。
- 广播格式随代际演进（TWS V1 / V2 / Advertise / 单耳类）。本插件**只实现 V1**，
  遇到其他格式会明确拒绝并给出诊断，不会误读。
- 同一区域内可能存在非 TWS 格式的 `0x0837` 广播（如 `payload[0]=0x85`），
  解析器会拒绝。
- 广播里的连接状态位只表示「耳机连着某个客户端」，**不区分连接对象**，
  也不影响电量可读性（双连接下电量照常可读）。
